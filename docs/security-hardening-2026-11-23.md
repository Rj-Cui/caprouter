# CapRouter Security Boundary Hardening Record (2026-11-23)

Corresponds to the P0 item in the handoff document `CapRouter-Task-Handoff-2026-11-23.md`. This record only describes landed behavior and verification results; it does not change the product positioning.

## 1. Fixed

### 1.1 state switch covers the execution surface

- `capabilities.invoke_capability` checks `is_enabled()` at the start; when disabled, both prompt and command modes return `blocked`, and it does not read the Card or execute commands.
- MCP `capability_invoke` reuses the same function, so it is covered automatically.
- `probes._run_command` returns `skipped` when state is disabled; static checks can still run.
- `adapters.run_adapter` adds a state check for non-Mock adapters, covering `review --semantic`, `synthesize refine --adapter`, `run --execute`, `host`.
- The existing state checks of `run --execute` / `host` are retained.

### 1.2 Card permissions take part in execution decisions

command invoke now requires all of the following:

1. `invoke.allow=true`;
2. `bus.allow_execute=true`;
3. the caller `allow_execute=true`;
4. the Card explicitly declares `permissions`, and `permissions.shell=true`;
5. `permissions.fs` is a string list containing `read`, and may only contain `read` / `write`;
6. the working directory is inside the workspace or the Card directory and must already exist; the default working directory is `.caprouter/scratch`.

Behavior change: Cards generated by scan have no permissions and cannot execute commands directly; they must go through draft → review → apply, or a human must explicitly write `shell=true` in the overlay.

### 1.3 guard rewrite

`caprouter/guard.py` now parses by argv (`shlex`) instead of substring matching:

- only allows the `caprouter` executable, `python <plugin>/bin/caprouter.py`, `python -m caprouter`, equivalent forms of `uv run`, `uvx caprouter`, `cd`;
- `python -c`, `python -`, `python evil.py caprouter.py`, `python -m caprouter.evil`, `uv run evil.py caprouter` are all rejected;
- `>`, `<`, `` ` ``, `(`, `)`, a single `&`, `$(`, `${` outside quotes are all rejected;
- argument text inside quotes is preserved (e.g. `--need "a > b"`);
- `&&`, `||`, `;`, `|` are still split into segments, and each segment must pass independently.

### 1.4 install uninitialized

`install_source` checks that `.caprouter/config.json` exists and the schema is `caprouter.config.v1`; otherwise it returns `not_initialized`, does not create the `.caprouter` directory, and does not write a partial config.

### 1.5 Write path hardening

- `capability invoke`'s `cwd` is no longer resolved arbitrarily and no longer auto-mkdir'd;
- `backup --label` goes through `safe_name` and cannot escape `backups/`;
- install targets and migrated draft names already use `safe_name`.

### 1.6 Audit

Execution and rejection decisions are written to `audit.jsonl` (`CAPROUTER_AUDIT` can override the path), with the event name `capability_invoke`, including workspace, capability id, decision, reason.

### 1.7 review scan scope

`review._draft_files` now collects both `.caprouter/drafts/*.json` (generated by install) and `.caprouter/drafts/projects/*.json`. Previously it only scanned projects, so cards generated by install would never be reviewed.

### 1.8 overlay unreachable Card

`apply_draft` checks whether the id exists in the registry before writing the overlay; if not, it returns `status=unreachable` and does not write the overlay. `review --auto-apply` no longer counts this as applied; `capability draft --apply` likewise returns a non-zero exit code and prints the reason.

### 1.9 status / runs

`collect_status` first reads the `run.json` written by the executor and falls back to the dispatch/dry-run `summary.json`, and outputs `status` / `created_at`. Previously it only read summary.json, so execution records were always empty.

### 1.10 same-second refine / improve

`refine_candidate` and `improve_synthesis` use `_unique_dir`: repeated runs within the same second automatically append `-2`, `-3` to the directory name, and no longer throw an uncaught `FileExistsError` due to `exist_ok=False`.

### 1.11 Online discovery isolation (discover / fetch / vendor)

- `discover` only reads the skills.sh search API, does not download;
- `fetch` only writes to `.caprouter/quarantine/`, validates relative paths, file count (≤500), total size (≤20MB), does not install or execute;
- `vendor` only reads quarantine, generates `deconstruction.md` and `card_draft.json`, does not install;
- explicit `--allow-network` is required; only the `skills.sh` domain is allowed; when `state` is disabled all three are rejected;
- install still goes through `install --approve`; after downloaded content enters `installed`, `review` / `apply` are still required;
- `fetch` reads `LICENSE`/`COPYING` to identify common licenses and writes them into provenance and the vendor report; unrecognized is written as `unknown`;
- `quarantine list` is read-only; `quarantine clean` previews by default and only deletes with `--yes`; the delete target must be inside the quarantine;
- `discover` client-side pagination (first 100), request interval 0.5s, one retry on 5xx/429; 429 returns an explicit rate-limit error;
- `uninstall` / `rollback` preview by default, execute only with `--yes`; only targets inside `installed/` are allowed; uninstalled directories move to `.trash`, and rollback restores the directory and Card;
- the whole process writes audit records (`remote_discover` / `remote_fetch` / `remote_vendor` / `quarantine_clean`).

## 3. Residual risks (must be reported honestly)

1. **net cannot be enforced**: there is no local OS-level sandbox and subprocesses can still access the network; `permissions.net` is only a declaration. Use containers/firewalls when hard isolation is needed. `permissions_enforcement.net` in invoke results is marked `advisory`.
2. **fs writes cannot be fully enforced**: cwd is restricted to the workspace/Card, but subprocesses can still write anywhere with absolute paths. `fs=read` cannot stop a malicious command from writing to disk.
3. **scan's `--version` probing is not constrained by state**: `scan_agents` and `adapters.probe` still execute the local CLI's `--version`, which is read-only diagnostics; a stricter switch can be added later if needed.
4. **bus mode guard does not intercept the host**: this is the original design; Card permissions and state are gated at the capability layer; do not treat guard as the only line of defense in bus mode.
5. **No OS-level isolation, no concurrency/performance tests**: the MCP parameter limits, symlinks and real adapter isolation from the handoff document still have no tests.
6. **Usability cost of command Cards**: explicit `shell=true` invalidates old hand-written overlays; this is a deliberate secure default, and Cards should be updated after review when needed.
